# Data Model: DevDocs AI MVP

**Branch**: `001-devdocs-ai-mvp` | **Date**: 2026-04-01

All tables use Supabase PostgreSQL. Row Level Security (RLS) is enabled on every table.
All timestamps are `timestamptz`. All primary keys are `uuid` generated by `gen_random_uuid()`.

---

## Entities

### 1. profiles

Extends Supabase Auth's `auth.users` table with app-specific fields. Created automatically
via a `AFTER INSERT ON auth.users` trigger on first sign-up.

| Column | Type | Constraints | Description |
|--------|------|-------------|-------------|
| `id` | `uuid` | PK, FK → `auth.users.id`, ON DELETE CASCADE | Supabase Auth user ID |
| `display_name` | `text` | nullable | User's chosen display name |
| `api_key_hash` | `text` | nullable | SHA-256 hash of API key for verification (key itself never stored) |
| `plan` | `text` | NOT NULL, DEFAULT `'free'`, CHECK IN (`'free'`, `'pro'`, `'team'`) | Subscription tier |
| `created_at` | `timestamptz` | NOT NULL, DEFAULT `now()` | Account creation |
| `updated_at` | `timestamptz` | NOT NULL, DEFAULT `now()` | Last profile update |

**Indexes**:
- Primary key on `id`

**RLS Policies**:
```sql
-- Users can only read their own profile
CREATE POLICY "profiles_select_own" ON profiles
  FOR SELECT USING (auth.uid() = id);

-- Users can only update their own profile
CREATE POLICY "profiles_update_own" ON profiles
  FOR UPDATE USING (auth.uid() = id);
```

**Trigger** (auto-create profile on sign-up):
```sql
CREATE OR REPLACE FUNCTION handle_new_user()
RETURNS TRIGGER AS $$
BEGIN
  INSERT INTO profiles (id, created_at, updated_at)
  VALUES (NEW.id, now(), now());
  RETURN NEW;
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;

CREATE TRIGGER on_auth_user_created
  AFTER INSERT ON auth.users
  FOR EACH ROW EXECUTE FUNCTION handle_new_user();
```

### 2. projects

A planning session. Stores the project metadata and the full interview Q&A as JSONB.

| Column | Type | Constraints | Description |
|--------|------|-------------|-------------|
| `id` | `uuid` | PK, DEFAULT `gen_random_uuid()` | Project identifier |
| `user_id` | `uuid` | NOT NULL, FK → `profiles.id`, ON DELETE CASCADE | Owning user |
| `name` | `text` | NOT NULL | Project display name |
| `status` | `text` | NOT NULL, DEFAULT `'in_progress'`, CHECK IN (`'in_progress'`, `'complete'`, `'archived'`) | Project status |
| `project_type` | `text` | NOT NULL, CHECK IN (`'saas'`, `'api'`, `'internal_tool'`, `'mobile'`, `'landing_page'`, `'other'`) | Project type / template |
| `interview_data` | `jsonb` | NOT NULL, DEFAULT `'{}'` | Full interview Q&A and state |
| `created_at` | `timestamptz` | NOT NULL, DEFAULT `now()` | Project creation |
| `updated_at` | `timestamptz` | NOT NULL, DEFAULT `now()` | Last modification |
| `deleted_at` | `timestamptz` | nullable | Soft delete timestamp. NULL = not deleted. |

**`interview_data` JSONB shape**:
```json
{
  "status": "interviewing",
  "currentDomain": "database",
  "completedDomains": ["planning", "architecture"],
  "domainContent": {
    "planning": "# Planning\n...",
    "architecture": "# Architecture\n..."
  },
  "conversationHistory": [
    { "role": "user", "content": "I want to build a SaaS..." },
    { "role": "assistant", "content": "Great! Let's start with..." }
  ]
}
```

**Indexes**:
- Primary key on `id`
- Index on `user_id` (for dashboard queries)
- Index on `(user_id, deleted_at)` (for filtered dashboard queries)
- Index on `updated_at DESC` (for sorted dashboard)

**RLS Policies**:
```sql
-- Users can only select their own non-deleted projects
CREATE POLICY "projects_select_own" ON projects
  FOR SELECT USING (auth.uid() = user_id AND deleted_at IS NULL);

-- Users can insert their own projects
CREATE POLICY "projects_insert_own" ON projects
  FOR INSERT WITH CHECK (auth.uid() = user_id);

-- Users can update their own projects
CREATE POLICY "projects_update_own" ON projects
  FOR UPDATE USING (auth.uid() = user_id);

-- No hard deletes via RLS — soft delete only via UPDATE
-- (actual DELETE operations are blocked at application layer)
```

**Free tier enforcement** (application layer, not DB):
The API route `POST /api/projects` checks active project count before insert:
```sql
SELECT COUNT(*) FROM projects
WHERE user_id = $1 AND deleted_at IS NULL;
```
If count ≥ 3 and `plan = 'free'`, return HTTP 402 with upgrade prompt.

### 3. documentation_bundles

The 10-file documentation output generated from a completed project interview. Versioned to
support future regeneration tracking.

| Column | Type | Constraints | Description |
|--------|------|-------------|-------------|
| `id` | `uuid` | PK, DEFAULT `gen_random_uuid()` | Bundle identifier |
| `project_id` | `uuid` | NOT NULL, FK → `projects.id`, ON DELETE CASCADE | Parent project |
| `version` | `integer` | NOT NULL, DEFAULT `1` | Bundle version (increments on full regeneration) |
| `files` | `jsonb` | NOT NULL | Object keyed by filename, value is markdown string |
| `generated_at` | `timestamptz` | NOT NULL, DEFAULT `now()` | Generation timestamp |
| `model_used` | `text` | NOT NULL, DEFAULT `'claude-sonnet-4-6'` | AI model used |

**`files` JSONB shape**:
```json
{
  "PLANNING.md": "# Planning\n## Project Scope\n...",
  "ARCHITECTURE.md": "# Architecture\n## ADR-001\n...",
  "DATABASE.md": "# Database\n## Schema\n...",
  "API-CONTRACTS.md": "# API Contracts\n...",
  "ENV-STRATEGY.md": "# Environment Strategy\n...",
  "AUTH.md": "# Authentication\n...",
  "TESTING.md": "# Testing\n...",
  "MONITORING.md": "# Monitoring\n...",
  "FRONTEND.md": "# Frontend\n...",
  "DEPLOYMENT.md": "# Deployment\n..."
}
```

**Indexes**:
- Primary key on `id`
- Unique index on `(project_id, version)` — one bundle per version per project
- Index on `project_id` (for retrieval)

**RLS Policies**:
```sql
-- Users can read bundles for their own projects
CREATE POLICY "bundles_select_own" ON documentation_bundles
  FOR SELECT USING (
    EXISTS (
      SELECT 1 FROM projects
      WHERE projects.id = documentation_bundles.project_id
        AND projects.user_id = auth.uid()
    )
  );

-- Users can insert bundles for their own projects
CREATE POLICY "bundles_insert_own" ON documentation_bundles
  FOR INSERT WITH CHECK (
    EXISTS (
      SELECT 1 FROM projects
      WHERE projects.id = documentation_bundles.project_id
        AND projects.user_id = auth.uid()
    )
  );

-- Users can update bundles for their own projects (for section regeneration)
CREATE POLICY "bundles_update_own" ON documentation_bundles
  FOR UPDATE USING (
    EXISTS (
      SELECT 1 FROM projects
      WHERE projects.id = documentation_bundles.project_id
        AND projects.user_id = auth.uid()
    )
  );
```

### 4. share_links

Read-only share tokens for documentation bundles. The token grants read-only access to a
specific bundle without requiring authentication.

| Column | Type | Constraints | Description |
|--------|------|-------------|-------------|
| `id` | `uuid` | PK, DEFAULT `gen_random_uuid()` | Share link identifier |
| `bundle_id` | `uuid` | NOT NULL, FK → `documentation_bundles.id`, ON DELETE CASCADE | Target bundle |
| `token` | `text` | NOT NULL, UNIQUE | URL-safe random token (32 chars) |
| `created_by` | `uuid` | NOT NULL, FK → `profiles.id` | User who created the link |
| `created_at` | `timestamptz` | NOT NULL, DEFAULT `now()` | Creation timestamp |
| `expires_at` | `timestamptz` | nullable | Optional expiry (NULL = never expires) |

**MVP note on `expires_at`**: In the MVP, all share links are created with `expires_at = NULL`
(never expire). The column exists in the schema to avoid a breaking migration later, but the
UI does not expose expiry configuration and the application does not enforce expiry checks in
MVP. Expiry enforcement (`expires_at > now()` filter) is already present in the
`bundles_select_via_share` RLS policy, so enabling it in a future release requires only a UI
change — no schema migration.

**Indexes**:
- Primary key on `id`
- Unique index on `token` (for fast lookup in share view)
- Index on `bundle_id`

**RLS Policies**:
```sql
-- Anyone (including unauthenticated) can read a valid share link by token
-- This enables the read-only share view without requiring login
CREATE POLICY "share_links_select_by_token" ON share_links
  FOR SELECT USING (true);

-- Only authenticated users can create share links for their own bundles
CREATE POLICY "share_links_insert_own" ON share_links
  FOR INSERT WITH CHECK (
    auth.uid() = created_by AND
    EXISTS (
      SELECT 1 FROM documentation_bundles b
      JOIN projects p ON p.id = b.project_id
      WHERE b.id = share_links.bundle_id
        AND p.user_id = auth.uid()
    )
  );

-- Users can delete their own share links
CREATE POLICY "share_links_delete_own" ON share_links
  FOR DELETE USING (auth.uid() = created_by);
```

**Note on read-only share access**: The `GET /share/[token]` page fetches the bundle via
the share token using the Supabase anon key. The RLS policy on `documentation_bundles`
also allows read access when a valid share token exists:
```sql
-- Additional bundle select policy for share access
CREATE POLICY "bundles_select_via_share" ON documentation_bundles
  FOR SELECT USING (
    EXISTS (
      SELECT 1 FROM share_links
      WHERE share_links.bundle_id = documentation_bundles.id
        AND (share_links.expires_at IS NULL OR share_links.expires_at > now())
    )
  );
```

## Migration Files

```text
supabase/migrations/
├── 001_create_profiles.sql       — profiles table + auto-create trigger
├── 002_create_projects.sql       — projects table + indexes
├── 003_create_bundles.sql        — documentation_bundles + share_links tables
```

All migrations are non-destructive. Production migrations only add columns/tables.
Dropping requires a deprecation period: mark as nullable first → deploy → remove in next release.
